# packages/session/

interaction model ของ Battle แบบไม่มี UI (ADR 0004): สิ่งที่ผู้เล่นทำได้ ณ ตอนนี้ คำนวณจาก engine แล้วส่งให้ battle (Phaser) และ web (React) วาด

**เจ้าของ:** Claude (ADR 0004) battle และ web เป็นของ Codex และใช้ package นี้ผ่าน `src/index.ts` เท่านั้น snapshot API และ port type เป็นสัญญา: เปลี่ยนแบบเพิ่มเท่านั้น Codex ขอการเปลี่ยนผ่าน ticket

## เก็บอะไร
- `src/session.ts`: `createBattleSession(state, { ai? })` store เดียวที่ React (`useSyncExternalStore`) และ Phaser อ่าน การเลือก Unit, การเล็ง (Basic Attack, skill แบบ Unit/ช่อง/พื้นที่, Command, Attune), action ที่ทำได้, preview, หน้า Hotseat (ส่งเครื่อง, initiative), Inspiration และการสั่ง AI ทีละขั้น (`aiStep`), `idleUnits`, และข้อมูลเตือนก่อนทิ้ง Action (phase 1.x ticket 01, เพิ่มอย่างเดียว): `snapshot.actionAtStake` (Unit ที่เล่นอยู่และยังใช้ Action ได้ การเริ่ม Unit อื่นจะเสีย Action นั้น) และ `snapshot.movedWithoutAction` (Unit ที่เดินแล้วแต่ยังไม่ใช้ Action และยังใช้ได้) พร้อม `actionAtStake(state)` / `movedWithoutAction(state)` ที่เรียกกับ state ตรงๆ ได้ Basic Attack, Defend และ skill ที่ไม่ฟรีนับเป็น Action, การเดินและ Camouflage ไม่นับ ไม่มีกติกาของตัวเอง ทุกอย่างมาจาก `legalActions` / `previewAction` / `applyAction` / `unitSkills` / `unitsVisibleTo`
- Undo (phase 1.x ticket 05, เพิ่มอย่างเดียว): `snapshot.undo` = `{ to: 'turnStart' | 'lastRoll', actions }` เมื่อฝั่งที่เล่นอยู่ (หน้าเครื่องนี้) ย้อนได้ (`undoPoint` ของ engine จากประวัติ state ที่ session เก็บ), `null` ถ้าไม่ได้ รวมทุกครั้งใน Turn ของ AI และหน้าส่งเครื่อง `undo()` คืน Battle ถึงจุดนั้น: state, activation, รายการ action และ log กลับตามจุด ลูกเต๋าไม่ขยับ `events` ว่าง (ไม่มีอะไรให้เล่น animation) `revision` เพิ่ม (view ต้องวาดใหม่ทั้งกระดาน) ไม่เลือก Unit ใด (เว้นแต่รอขั้นถอยของ Hit and Run) `snapshot.actions` จึงมีแค่ action ที่คงอยู่ Replay ที่ export ระหว่างนี้ไม่มีรอย Undo (ticket 06)
- Undo ปุ่มซ่อน/ปิด (P1X-33, เพิ่มอย่างเดียว, ไม่ bump ENGINE_VERSION): `snapshot.undoState` = `{ kind: 'hidden' }` (Turn ของ AI, หน้าส่งเครื่อง/initiative/decisionHandoff, deployment, Battle จบ: ไม่วาดปุ่ม) | `{ kind: 'disabled', reason: 'turn-start' | 'after-roll' }` (วาดปุ่มแต่กดไม่ได้: ยังไม่มี action ใน Turn นี้ / action ล่าสุดทอยลูกเต๋าหรือเป็นคำตอบ Inspiration) | `{ kind: 'available', offer }` (`offer` เท่ากับ `snapshot.undo`) `reason` เป็น code ข้อความอยู่ใน web **UI ต้องอ่าน field นี้ ห้ามคิดกติกาการซ่อนเอง** (side to act, phase, outcome, screen) `snapshot.undo` ความหมายเดิม `undo()` คืน `boolean` ว่าย้อนจริงหรือไม่ (`false` = ไม่ทำอะไร)
- Move preview (phase 1.x ticket 03, เพิ่มอย่างเดียว): `previewMove(tile)` เลือกช่องที่เดินถึงเพื่อดู (Unit ที่เลือก, โหมดเดิน, ช่องต้องอยู่ใน `reachable`) `snapshot.movePreviewTile` เก็บช่องนั้น (สถานะ UI ไม่ใช่สถานะเกม; `previewMove` ช่องอื่นแทนที่, `cancelMovePreview()` หรือ `cancel()` ยกเลิก, เลือก Unit อื่นหรือ action สำเร็จก็ล้าง) `snapshot.movePreview` คือ `{ unit, tile, skill, reach }` ที่ engine คิดให้ราวกับ Unit ยืนที่ช่องนั้น: ใช้ `applyAction` กับสำเนา state (ไม่เปลี่ยน Battle จริง ไม่ใช้ลูกเต๋า) แล้วอ่าน `legalActions` ของผลลัพธ์ `reach` มี Basic Attack (`skill: null`) และ skill โจมตี/save ที่พร้อมใช้ (cooldown 0, ไม่ใช่ free, ไม่ใช่ skill ที่พาไปช่องนั้น) แต่ละรายการบอก `targets` (ศัตรูที่ถึง) และ `blocked` (ศัตรูในระยะที่ line of sight หรือ Hidden บัง) Blink ใช้ flow เดิมของ skill (`chooseSkill('blink')` แล้วแตะช่อง) `movePreview.skill` เป็น `'blink'` และคิดเหมือนกัน `confirmMove()` เดินจริง (`move`) หรือ Blink Unit ที่เดินแล้วไม่มี `reachable` จึงไม่มี preview การแตะช่องผ่าน `input` ยังเดินทันทีเหมือนเดิมจนกว่า UI จะเปลี่ยน (ticket 04) แตะ Unit ที่เลือกอยู่ขณะมี preview (`selectUnit` หรือ `input` `tapUnit`) ยกเลิกแค่ preview: Unit ยังเลือกอยู่ โหมดเดิม (เดิน: ช่องยังสว่าง; Blink: ยังเล็ง Blink แต่ไม่มีช่องที่เลือก) แตะอีกครั้งจึงยกเลิกการเลือก (ticket 18) `BattleSnapshot.movePreview?` (port) มีค่าเดียวกับ `SessionSnapshot.movePreview` Replay player ให้ `null`
- Threat zone (phase 1.x ticket 11, เพิ่มอย่างเดียว): `movePreview.threat` = จำนวนศัตรูที่อาจโจมตีช่องที่ดู (หรือปลายทาง Blink) ใน Turn หน้าของอีกฝั่ง, `snapshot.threatZone[y][x]` (และ `BattleSnapshot.threatZone?` ใน port; Replay player ไม่ให้ค่านี้) = จำนวนเดียวกันของทุกช่องสำหรับฝั่งที่เห็น Board (Hotseat: ฝั่งที่เล่น, vs AI: ฝั่งมนุษย์; ว่างนอกช่วง play) ใช้ทำ overlay เปิด/ปิดทั้ง Board. นับแบบหยาบตามนิยามใน CONTEXT.md (ดู `threatCount` ใน engine) เป็นคำแนะนำ ไม่ใช่การรับประกัน. Action plan ใช้จำนวนนี้เป็นตัวตัดสินลำดับที่ 2 ของช่องที่ยืนโจมตี (ช่องเดิม → ก้าวน้อยสุด → Threat zone ต่ำสุด → ลำดับช่อง) บนบอร์ด 7x7 ศัตรูส่วนใหญ่ครอบทั้งบอร์ด (ระยะเดิน + ระยะ skill ≥ 6) ตัวเลขจึงต่างกันระหว่างช่องน้อย
- Action plan (phase 1.x ticket 23, เพิ่มอย่างเดียว, ไม่มี action ใหม่ใน engine จึงไม่ bump ENGINE_VERSION; `src/actionPlan.ts`): เลือกเป้าก่อนแล้วเกมเลือกช่องที่ยืนโจมตี ยืนยันครั้งเดียวส่ง Move (หรือ Blink) ตามด้วย Action เดิม ทุกอย่างคิดโดย engine บนสำเนา Battle (apply Move/Blink แล้วอ่าน `legalActions`) จึงตรงกับการเล่นจริงเสมอ ไม่ทอยลูกเต๋า ไม่เปลี่ยน Battle. `snapshot.attackable` = ศัตรูที่ Unit ที่เลือกโจมตีได้ใน activation นี้ `{ unit, tile, fromHere, origins }` โดย `origins` คือช่องที่ยืนโจมตีได้ `{ tile, via: 'stay' | 'move' | 'blink', steps }` เรียงดีสุดก่อน (ช่องแรกคือที่เกมเสนอ) กฎเลือกช่อง: ช่องเดิมถ้าอยู่ในระยะ (โจมตีก่อนเดินและ Hit and Run ยังใช้ได้) → ก้าวน้อยสุด → ลำดับช่อง (y แล้ว x) Blink มาหลังการเดินทุกแบบ (เปลือง skill เกมไม่เลือกให้เอง) ช่องที่ทั้งเดินและ Blink ถึง ค่าเริ่มคือเดิน. คำสั่ง: `aimTarget(unit)` เลือกเป้าจาก `attackable` (มี Move preview อยู่และช่องเงาตีเป้านั้นได้ → ใช้ช่องเงา มิฉะนั้นตามกฎ), `chooseOrigin(tile, via?)` เปลี่ยนช่องในบรรดา `plan.originChoices`, `choosePlanAction(key)` เลือก action ใน `plan.choices` หรือใน `movePreview.options` (ศัตรูอื่นที่ตีได้จากช่องเงา, Defend, skill ช่วยพวกเดียวกัน, skill ไม่มีเป้า) แล้วเกิด plan ที่ไม่มีเป้า, `confirmPlan()` ส่ง `plan.steps` ทั้งหมดหรือไม่ส่งเลย (ถ้า engine ปฏิเสธขั้นไหน Move ก็ไม่เกิด; `snapshot.rejection` บอกเหตุผล) `cancel()` ถอยทีละขั้น: plan → Move preview → การเลือก, แตะ Unit ที่เลือกอยู่ยกเลิกแค่ plan, การแตะบน Board ไม่ส่งอะไร: ระหว่างมี plan `input` แตะช่องที่เป็นหนึ่งใน `originChoices` = `chooseOrigin` ช่องอื่นไม่ทำอะไรและ plan อยู่ต่อ (แตะช่องที่สว่างโดยไม่มี plan ยังเดินทันทีเหมือนเดิม). `snapshot.plan` = `{ unit, target, origin, originChoices, choices, choice, preview, steps, rolls, abandons }`: `choices` คือสิ่งที่ทำได้จากช่องนั้น (โจมตีเป้าก่อน แล้ว Defend / skill อื่น), `preview` คือโอกาสโดนและ damage ของ `choice` จาก `previewAction` บนสำเนาหลังเดิน, `rolls` บอกว่าจะทอยลูกเต๋า (ยืนยันแล้ว Undo ย้อนข้ามไม่ได้ ตามกฎจุดปลอดภัยเดิม; Move + Defend ย้อนได้ทั้งคู่), `abandons` คือ Unit ที่ยืนยันแล้วจะเลิกเล่นทั้งที่ยังมี Action (guard ของ ticket 02: UI ถามก่อนเหมือน `actionAtStake`) ที่เก็บ UI state: `planTarget`, `planOrigin`, `planChoice`. `snapshot.eventBatches` (และ `BattleSnapshot.eventBatches?`) = events ของแต่ละ action ที่คำสั่งล่าสุดส่ง ตามลำดับ (Move แล้ว Action) เพื่อให้ view เดินก่อนโจมตี; `events` ยังเป็นของ action สุดท้าย และ `revision` เพิ่มทีละ action. Replay มี 2 action เหมือนเล่นทีละขั้น. ไม่ทำงานระหว่าง pending, Turn ของ AI หรือหน้าจอส่งเครื่อง. Burst เป็นตัวเลือกโจมตีได้เมื่อมีท่าที่โดนศัตรูตัวนั้นตัวเดียว ส่วน Camouflage (free) และ Command ไม่อยู่ใน plan. `movePreview.options` เป็น field ใหม่ของ Move preview (เพิ่มอย่างเดียว). Engine เพิ่ม export `pathTo` (helper นับก้าว ไม่เปลี่ยนผลของ action ใด)

## แนวทาง/กฎการตั้งชื่อ
- dependency: `@mt/shared`, `@mt/engine`, `@mt/ai` เท่านั้น ห้าม import battle, web, React, Phaser
- กติกาของระยะ (P1X-09 และ P1X-27): `@mt/session` re-export `RangeRules`, `GAME_RANGE_RULES` (disadvantage ระยะไกลตั้งแต่ระยะ 4, ภูเขาบังแนวเล็ง) และ `NO_RANGE_RULES` (กติกาก่อน ticket 09 สำหรับ tools) `AttackPreview.rollMode` รวม disadvantage ระยะไกลแล้ว ซึ่งอยู่ใน flag `AttackPreview.longRangeDisadvantage` ไม่ใช่ `rollModeSources` UI ต้องอ่านทั้งสองอย่างเพื่ออธิบายเหตุผลของการทอย
- ไม่มีข้อความที่ผู้เล่นเห็น (ไม่มีภาษาไทยใน `src/`): session ให้ข้อมูล (event, action, enum เช่น `rejection`, `blocked[].reason`) แล้ว web แปลงเป็นข้อความด้วย `strings.ts` / `skillText.ts` / `describeAction`
- ไม่แตะ DOM, เวลาจริง, timer หรือการสุ่ม: delay ระหว่าง action ของ AI อยู่ใน web (`App.tsx`), นาฬิกาของ playStats ส่งเข้ามา (`Date` ใช้เป็น type ได้ แต่สร้างเวลาเองไม่ได้)
- `test/boundaries.test.ts` ตรวจทั้งหมดนี้ (แบบเดียวกับ engine)
